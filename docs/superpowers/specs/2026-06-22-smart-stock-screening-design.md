# 智能选股中心与混合数据网关设计

日期：2026-06-22  
产品：老马智能股票盯盘助手  
状态：待用户最终确认

## 1. 目标

在现有研究中心基础上新增可实际运行的“智能选股中心”，融合 GO-STOCK 形态选股、指标选股、热门/自定义策略和推荐记录的有效思路。系统以数据质量为第一优先级：免费多源完成全A扫描，候选池与自选股通过统一接口预留付费低延迟行情源。

本功能输出的是候选与验证记录，不承诺收益，也不把 AI 结论等同于交易指令。

## 2. 范围

本期包含：

- 全A批量行情快照与历史K线数据网关。
- Redis 热缓存和数据来源、时点、延迟、陈旧状态记录。
- 形态选股、指标选股、热门策略、自定义策略。
- 自然语言条件转为受控策略表达式，并经过服务端白名单校验。
- 推荐记录、推荐价快照、1/3/5/10日收益、最大回撤和触发状态。
- “形态选股、指标选股、推荐验证、数据健康”四个页签。
- 扫描、策略保存、加入自选、AI复核、导出和推荐预警交互。

本期不包含：

- 自动下单和券商交易接口。
- 未授权的逐笔、盘口队列或Level-2数据。
- 将大模型生成的任意代码直接执行。
- 复制 GO-STOCK GPL 源代码。

## 3. 架构

### 3.1 数据网关

建立统一 `MarketDataGateway`，上层不直接调用具体网站：

- 全市场扫描：优先使用东方财富批量行情，腾讯/新浪作为基础行情备用源。
- 历史K线：Tushare、AKShare、东方财富按配置和可用性切换。
- 财务、估值、资金、公告和研报：复用现有 Tushare 与东方财富适配器。
- 付费源：定义 `PremiumQuoteAdapter` 接口，未配置时不影响免费扫描。

每次返回都必须携带 `source`、`fetched_at`、`latency_ms`、`is_stale`、`fallback_used` 和 `errors`。主源失败时由网关切换备用源；所有源失败时返回明确的不可用状态，不返回演示值。

禁止为全A扫描逐股发起HTTP请求。实时快照必须使用批量接口，历史数据采用按需获取和缓存。

### 3.2 缓存与存储

- Redis：全A快照2至5秒、候选池行情1至2秒、日K与指标15至60分钟、财务数据按交易日缓存。
- PostgreSQL：策略定义、扫描运行、推荐记录、收益快照、数据源健康历史。
- SQLite：桌面单机无 PostgreSQL 时的兼容存储。

缓存键包含市场、数据类型、代码、周期和复权方式。数据刷新采用“旧值可读、后台更新”，但陈旧数据必须显示警告。

### 3.3 策略引擎

确定性计算与 AI 分离：

- 形态规则：MACD/KDJ金叉、均线多头/空头、放量突破、低位资金流入、连续放量、跳空、阳包阴、趋势反转等。
- 指标规则：价格、涨跌幅、成交额、换手率、量比、市值、PE/PB、均线、MACD、RSI、KDJ、布林带、资金流和板块强度。
- 持续性规则：近3/5/7日命中次数、连续天数、排名稳定性。
- 组合逻辑：AND、OR、比较、区间、排序和结果数量限制。

自然语言选股只负责生成结构化 DSL，例如：

```json
{
  "all": [
    {"field": "turnover_rate", "op": ">=", "value": 3},
    {"field": "pe_ttm", "op": "between", "value": [0, 30]},
    {"signal": "macd_golden_cross", "within_days": 3}
  ],
  "sort": [{"field": "main_net_inflow", "direction": "desc"}],
  "limit": 50
}
```

服务端仅执行白名单字段与操作符，设置最大结果数、最大条件数和查询超时。

### 3.4 推荐验证

推荐创建时固化以下快照：

- 股票、策略版本、命中条件和数据源。
- 推荐时间、推荐价、市场环境、板块强度。
- 建议观察区、失效价、止盈参考和风险说明。
- 使用的模型及 AI 复核结果；未使用 AI 时明确标记。

系统在后续交易日计算1/3/5/10日收益、区间最高收益、最大回撤、是否触发失效价。推荐记录不可被最新数据回写覆盖，避免未来函数和事后修改。

## 4. 页面与交互

智能选股中心复用现有导航、颜色、表格和面板样式，不照搬 GO-STOCK 外观。

### 4.1 形态选股

- 顶部为可多选的形态标签和持续性条件。
- 支持关键词、板块、市场、排除ST、价格/市值范围。
- 结果表展示股票、最新价、涨跌幅、命中形态、命中日期、数据时点和来源。
- 可加入自选、建立推荐记录、打开K线和发起AI复核。

### 4.2 指标选股

- 左侧显示热门策略和我的策略。
- 主区提供自然语言输入、可视化条件编辑和扫描按钮。
- 扫描前展示解析后的结构化条件；用户确认后执行。
- 策略可保存、复制、编辑和停用。

### 4.3 推荐验证

- 展示推荐时与当前价格、累计收益、最大回撤、持有交易日和触发状态。
- 支持模型、策略、日期、收益和预警状态筛选。
- 查看详情时展示K线、推荐价/止损/止盈参考线和原始证据。

### 4.4 数据健康

- 每个源显示可用状态、最近成功时间、平均延迟、错误率、缓存命中率和当前角色。
- 显示当前是否使用备用源以及数据新鲜度。
- 管理员可测试数据源；普通用户只能查看状态。

## 5. API 边界

- `GET /api/screener/catalog`：支持的字段、形态和热门策略。
- `POST /api/screener/parse`：自然语言转 DSL，不执行扫描。
- `POST /api/screener/run`：验证 DSL 后执行扫描。
- `GET/POST/PUT/DELETE /api/screener/strategies`：用户策略管理。
- `GET /api/recommendations/validation`：推荐验证列表。
- `POST /api/recommendations`：从扫描结果创建推荐快照。
- `GET /api/data-sources/health`：数据源健康状态。

所有接口应用现有登录身份；策略和推荐按用户隔离，数据源配置仅管理员可写。

## 6. 性能与刷新目标

- 缓存命中时，全A基础扫描目标响应时间小于2秒。
- 冷启动全A基础扫描目标小于8秒。
- 候选池行情刷新目标1至2秒；免费源受限时允许退化到5秒并明确显示。
- 页面不因某个数据源超时整体阻塞；单源默认超时3至8秒并启用熔断。
- 复杂技术指标采用批量向量计算，计算结果按交易日和参数缓存。

这些是工程目标，不代表免费数据源本身提供交易所级实时性。

## 7. 风险与容错

- 反爬或限流：降频、缓存、备用源和指数退避，不伪装成功。
- 字段口径不同：网关统一单位和复权口径，并记录原始来源。
- 停牌、退市、ST、新股数据不足：在结果中标记，默认可排除。
- AI解析歧义：先展示 DSL，未经确认不执行；无法映射的条件返回错误。
- 未来函数：扫描只使用当时可获得的数据，推荐快照不可修改。
- 付费源未配置：系统保持免费模式并在数据健康页显示能力差异。

## 8. 测试与验收

- 数据适配器契约测试：字段、单位、时点和备用源切换。
- 策略单元测试：每个形态使用固定K线样本验证命中与不命中。
- DSL安全测试：拒绝未知字段、非法操作符、超大查询和代码注入。
- 无未来函数测试：任何扫描结果不得读取扫描时点之后的数据。
- 推荐收益测试：交易日计算、停牌处理和最大回撤口径准确。
- 性能测试：缓存命中、冷启动和数据源超时场景。
- 前端测试：筛选、策略保存、扫描、推荐记录和错误/陈旧状态。
- 发布前执行 Python 单测、编译检查、JavaScript语法检查、API冒烟和Windows安装包验证。

## 9. 实施顺序

1. 数据网关、批量全A快照和健康监控。
2. 策略 DSL、技术指标与形态计算。
3. 策略和推荐持久化、收益复盘任务。
4. 四页签智能选股中心及完整交互。
5. AI自然语言解析与AI复核。
6. 性能、容错、安装包和交付验证。

## 10. 验收定义

用户可以在真实数据可用时完成一次全A形态或指标扫描，确认数据来源和更新时间，将结果保存为推荐记录，并在后续交易日看到可复现的收益与回撤；任一数据源失败时系统会显示降级状态而不是演示数据或静默失败。
